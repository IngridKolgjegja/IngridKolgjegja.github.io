Power BI Relationships Explained

Relationships are one of the most important parts of a Power BI data model. If your relationships are wrong, filters, measures and visuals can behave in unexpected ways.

What is a relationship in Power BI?

A relationship connects two tables through columns that contain matching values.

For example, imagine you have:

  • a Sales table
  • a Products table

Both tables contain a product ID. 

Sales[ProductID]

Products[ProductID]

Power BI can use these columns to connect the tables.

One-to-many relationships

The most common relationship in Power BI is one-to-many.

For example: 

Products[ProductID]  1 → *  Sales[ProductID]

The Products table contains one row per product, while the Sales table can contain many rows for the same product.

Good practice: dimension tables usually sit on the "one" side and fact tables on the "many" side.

Why relationships matter

Relationships allow filters to move between tables.

If you use: 

Products[Category]

in a slicer, Power BI can use the relationship to filter the rows in the Sales table.

Active and inactive relationships

Power BI allows multiple relationships between two tables, but normally only one can be active at a time.

An active relationship is shown with a solid line in Model view.

An inactive relationship is shown with a dashed line.

Inactive relationships can still be used inside DAX with functions such as: 

USERELATIONSHIP()

Cross-filter direction

Relationships also have a cross-filter direction.

The two main options are:

  • Single
  • Both

Single-direction filtering is usually easier to understand and control.

Bidirectional filtering can be useful in some models, but it can also create ambiguity or unexpected filter behavior.

Common relationship problems

1. Duplicate values on the "one" side

If the supposed dimension table contains duplicate keys, Power BI may not allow a one-to-many relationship.

2. Different data types

The two columns used in the relationship should have compatible data types.

For example, one column should not be text while the other is numeric.

3. Missing relationships

If two tables are not connected, filters may not propagate between them.

4. Wrong cardinality

Always check whether the relationship should be:

  • one-to-many
  • many-to-one
  • one-to-one
  • many-to-many

Star schema

A common Power BI model uses a star schema.

A central fact table is connected to several dimension tables. 

          Customers
              |
              |
Products — Sales — Calendar
              |
              |
           Regions

This structure usually makes filtering and DAX easier to manage.

Quick checklist

  • Are the correct columns connected?
  • Are the data types compatible?
  • Is the relationship active?
  • Is the cardinality correct?
  • Is the filter direction appropriate?
  • Does the dimension table contain unique keys?
