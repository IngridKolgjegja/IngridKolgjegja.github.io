SQL JOINs Explained

JOINs are one of the most important concepts in SQL because real-world data is usually split across multiple tables.

JOINs allow you to combine related data using a common key.

Example tables

Imagine you have two tables:

customers

customer_id | customer_name | country
1           | Anna          | Italy
2           | Marco         | France
3           | Sofia         | Spain

orders

order_id | customer_id | amount
101      | 1           | 500
102      | 1           | 300
103      | 2           | 700
104      | 4           | 200

The common field is: 

customer_id

INNER JOIN

An INNER JOIN returns only rows that have matching values in both tables. 

SELECT
    c.customer_name,
    o.order_id,
    o.amount
FROM customers c
INNER JOIN orders o
    ON c.customer_id = o.customer_id;

This returns customers that have matching orders.

Think of INNER JOIN as: keep only the records that exist in both tables.

LEFT JOIN

A LEFT JOIN returns all rows from the left table and matching rows from the right table. 

SELECT
    c.customer_name,
    o.order_id,
    o.amount
FROM customers c
LEFT JOIN orders o
    ON c.customer_id = o.customer_id;

Customers without orders are still returned, but the order columns will contain NULL.

Why LEFT JOIN is useful for analysts

LEFT JOIN is extremely useful when you want to identify missing activity.

For example:

  • customers with no orders
  • products with no sales
  • employees with no recorded activity
  • accounts with no transactions

Example: 

SELECT
    c.customer_id,
    c.customer_name
FROM customers c
LEFT JOIN orders o
    ON c.customer_id = o.customer_id
WHERE o.order_id IS NULL;

This returns customers who have never placed an order.

RIGHT JOIN

A RIGHT JOIN returns all rows from the right table and matching rows from the left table. 

SELECT
    c.customer_name,
    o.order_id,
    o.amount
FROM customers c
RIGHT JOIN orders o
    ON c.customer_id = o.customer_id;

In practice, many analysts use LEFT JOIN more often because you can usually reverse the table order and get the same logic more clearly.

FULL OUTER JOIN

A FULL OUTER JOIN returns:

  • matching rows
  • unmatched rows from the left table
  • unmatched rows from the right table
SELECT
    c.customer_name,
    o.order_id,
    o.amount
FROM customers c
FULL OUTER JOIN orders o
    ON c.customer_id = o.customer_id;

This can be useful for reconciliation and data quality checks.

JOIN types summary

INNER JOIN
Only matching records

LEFT JOIN
All left-table records + matches

RIGHT JOIN
All right-table records + matches

FULL OUTER JOIN
Everything from both tables

Joining more than two tables

Real analysis often requires several joins.

Imagine: 

orders
customers
products

You could write: 

SELECT
    o.order_id,
    c.customer_name,
    p.product_name,
    o.amount
FROM orders o
LEFT JOIN customers c
    ON o.customer_id = c.customer_id
LEFT JOIN products p
    ON o.product_id = p.product_id;

This combines order information with both customer and product details.

Table aliases

Aliases make SQL queries shorter and easier to read. 

FROM customers c
LEFT JOIN orders o

Here: 

c = customers
o = orders

You can then write: 

c.customer_name
o.amount

Common JOIN mistake: missing ON condition

JOINs should use the correct matching key. 

ON customers.customer_id = orders.customer_id

Joining on the wrong columns can produce incorrect results.

Common JOIN mistake: duplicated rows

If the key is not unique in one or both tables, a JOIN can create more rows than expected.

For example, if customer 1 appears twice in the customer table and has three orders, the join can produce six rows.

Important: always understand the relationship between your tables before joining them.

Checking row counts

Before and after a JOIN, it is often useful to check the number of rows. 

SELECT COUNT(*)
FROM orders;

Then compare it with the result after the JOIN.

Unexpected increases in row count can indicate duplicate keys or many-to-many relationships.

Joining and aggregating

Analysts often join tables and then calculate KPIs.

Example: revenue by country. 

SELECT
    c.country,
    SUM(o.amount) AS total_revenue
FROM orders o
LEFT JOIN customers c
    ON o.customer_id = c.customer_id
GROUP BY c.country
ORDER BY total_revenue DESC;

Which JOIN should you use?

Ask yourself what you want to keep.

  • Use INNER JOIN when you only need records that match.
  • Use LEFT JOIN when you want to keep every record from your main table.
  • Use FULL OUTER JOIN when you need to identify records missing from either side.

Practical analyst example

Suppose you want to know:

How much revenue has each customer generated? 

SELECT
    c.customer_id,
    c.customer_name,
    SUM(o.amount) AS total_revenue
FROM customers c
LEFT JOIN orders o
    ON c.customer_id = o.customer_id
GROUP BY
    c.customer_id,
    c.customer_name
ORDER BY total_revenue DESC;

Using LEFT JOIN means customers with no orders can still appear in the result.

Quick checklist

  • What table should be your starting table?
  • What key connects the tables?
  • Is the key unique where you expect it to be?
  • Do you want unmatched records?
  • Did the row count increase unexpectedly?
  • Are NULL values expected after the JOIN?
