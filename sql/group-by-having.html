SQL GROUP BY and HAVING Explained

GROUP BY is one of the most important SQL tools for data analysis because it lets you summarise rows into meaningful groups.

Analysts use GROUP BY to answer questions such as:

  • What is total revenue by country?
  • How many customers are in each region?
  • What is average order value by product category?
  • Which markets generated more than €100,000 in sales?

Basic GROUP BY syntax

Imagine you have a sales table: 

sale_id | country | amount
1       | Italy   | 500
2       | Italy   | 300
3       | France  | 700
4       | Spain   | 400

To calculate total sales by country: 

SELECT
    country,
    SUM(amount) AS total_sales
FROM sales
GROUP BY country;

The result would look like: 

country | total_sales
Italy   | 800
France  | 700
Spain   | 400

GROUP BY with COUNT

You can count rows within each group. 

SELECT
    country,
    COUNT(*) AS number_of_sales
FROM sales
GROUP BY country;

COUNT DISTINCT

In data analysis, you often need the number of unique customers rather than the total number of rows. 

SELECT
    country,
    COUNT(DISTINCT customer_id) AS unique_customers
FROM sales
GROUP BY country;

GROUP BY with multiple columns

You can group by more than one field.

For example, revenue by country and product category: 

SELECT
    country,
    product_category,
    SUM(amount) AS total_sales
FROM sales
GROUP BY
    country,
    product_category;

SQL creates one group for each unique combination of country and product category.

Using AVG, MIN and MAX

GROUP BY works with all common aggregation functions. 

SELECT
    country,
    AVG(amount) AS average_sale,
    MIN(amount) AS smallest_sale,
    MAX(amount) AS largest_sale
FROM sales
GROUP BY country;

What is HAVING?

HAVING filters grouped results.

For example, suppose you only want countries with more than €1,000 in total sales. 

SELECT
    country,
    SUM(amount) AS total_sales
FROM sales
GROUP BY country
HAVING SUM(amount) > 1000;
Key difference: WHERE filters individual rows before aggregation. HAVING filters grouped results after aggregation.

WHERE vs HAVING

Consider this query: 

SELECT
    country,
    SUM(amount) AS total_sales
FROM sales
WHERE sale_date >= '2026-01-01'
GROUP BY country
HAVING SUM(amount) > 100000;

SQL first applies: 

WHERE sale_date >= '2026-01-01'

Then it groups the remaining rows by country.

Finally it applies: 

HAVING SUM(amount) > 100000

Practical example: high-value customers

Suppose you want to find customers who generated more than €5,000 in revenue. 

SELECT
    customer_id,
    SUM(amount) AS total_revenue
FROM sales
GROUP BY customer_id
HAVING SUM(amount) > 5000
ORDER BY total_revenue DESC;

Practical example: customers with multiple orders

To find customers who placed more than five orders: 

SELECT
    customer_id,
    COUNT(DISTINCT order_id) AS number_of_orders
FROM sales
GROUP BY customer_id
HAVING COUNT(DISTINCT order_id) > 5;

Practical example: average sales by region

SELECT
    region,
    AVG(amount) AS average_sale
FROM sales
GROUP BY region
ORDER BY average_sale DESC;

Joining and grouping

In real analysis, GROUP BY is often used after a JOIN.

Example: revenue by customer country. 

SELECT
    c.country,
    SUM(o.amount) AS total_revenue
FROM orders o
LEFT JOIN customers c
    ON o.customer_id = c.customer_id
GROUP BY c.country
ORDER BY total_revenue DESC;

Grouping by month

Analysts frequently aggregate data by time period.

The exact date syntax depends on the SQL database, but conceptually you might do: 

SELECT
    YEAR(order_date) AS year,
    MONTH(order_date) AS month,
    SUM(amount) AS monthly_revenue
FROM orders
GROUP BY
    YEAR(order_date),
    MONTH(order_date)
ORDER BY
    year,
    month;

Common mistake: selecting columns that are not grouped

Consider: 

SELECT
    country,
    customer_name,
    SUM(amount)
FROM sales
GROUP BY country;

This is usually invalid because customer_name is neither aggregated nor included in the GROUP BY.

A safer structure would be: 

SELECT
    country,
    customer_name,
    SUM(amount)
FROM sales
GROUP BY
    country,
    customer_name;

Common mistake: using WHERE with aggregate functions

This is incorrect: 

SELECT
    country,
    SUM(amount)
FROM sales
WHERE SUM(amount) > 1000
GROUP BY country;

Use HAVING instead: 

SELECT
    country,
    SUM(amount)
FROM sales
GROUP BY country
HAVING SUM(amount) > 1000;

GROUP BY for dashboard KPIs

GROUP BY is especially useful when preparing datasets for Power BI or other reporting tools.

For example: 

SELECT
    country,
    COUNT(DISTINCT customer_id) AS customers,
    COUNT(DISTINCT order_id) AS orders,
    SUM(amount) AS revenue,
    AVG(amount) AS average_sale
FROM sales
GROUP BY country;

This produces a compact analytical table containing several KPIs by country.

Quick checklist

  • What dimension do you want to group by?
  • What metric do you want to calculate?
  • Should you use SUM, COUNT, AVG, MIN or MAX?
  • Do you need WHERE to filter rows first?
  • Do you need HAVING to filter aggregated results?
  • Are all non-aggregated columns included in GROUP BY?
