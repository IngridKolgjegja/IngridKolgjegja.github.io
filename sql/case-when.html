SQL CASE WHEN Explained

CASE WHEN lets you create conditional logic inside a SQL query. It is extremely useful for segmentation, flags, categories and business reporting.

Basic syntax

CASE
    WHEN condition THEN result
    ELSE other_result
END

Simple example

Suppose you want to classify sales as high or low value. 

SELECT
    sale_id,
    amount,
    CASE
        WHEN amount >= 1000 THEN 'High Value'
        ELSE 'Low Value'
    END AS sales_category
FROM sales;

Multiple conditions

You can use several WHEN conditions. 

SELECT
    customer_id,
    total_spend,
    CASE
        WHEN total_spend >= 5000 THEN 'Gold'
        WHEN total_spend >= 2000 THEN 'Silver'
        WHEN total_spend >= 500 THEN 'Bronze'
        ELSE 'Standard'
    END AS customer_segment
FROM customers;
Important: SQL evaluates CASE conditions from top to bottom and stops at the first true condition.

CASE WHEN for business flags

CASE WHEN is often used to create simple flags. 

SELECT
    customer_id,
    last_order_date,
    CASE
        WHEN last_order_date >= '2026-09-01' THEN 1
        ELSE 0
    END AS active_customer
FROM customers;

This creates a binary flag that can later be used in reporting.

CASE WHEN with NULL values

You can use CASE WHEN to handle missing values. 

SELECT
    customer_name,
    CASE
        WHEN country IS NULL THEN 'Unknown'
        ELSE country
    END AS customer_country
FROM customers;

CASE WHEN with aggregation

CASE WHEN becomes especially powerful when combined with SUM or COUNT.

Example: calculate revenue from Italy only. 

SELECT
    SUM(
        CASE
            WHEN country = 'Italy' THEN amount
            ELSE 0
        END
    ) AS italy_revenue
FROM sales;

Conditional counts

You can count records that meet a condition. 

SELECT
    COUNT(
        CASE
            WHEN amount >= 1000 THEN 1
        END
    ) AS high_value_sales
FROM sales;

Conditional KPIs

Analysts often use CASE WHEN to calculate several KPIs in one query. 

SELECT
    SUM(amount) AS total_revenue,

    SUM(
        CASE
            WHEN country = 'Italy' THEN amount
            ELSE 0
        END
    ) AS italy_revenue,

    SUM(
        CASE
            WHEN country = 'France' THEN amount
            ELSE 0
        END
    ) AS france_revenue

FROM sales;

CASE WHEN with GROUP BY

You can create categories and aggregate them. 

SELECT
    CASE
        WHEN amount >= 1000 THEN 'High Value'
        WHEN amount >= 500 THEN 'Medium Value'
        ELSE 'Low Value'
    END AS sales_category,

    COUNT(*) AS number_of_sales,
    SUM(amount) AS total_revenue

FROM sales

GROUP BY
    CASE
        WHEN amount >= 1000 THEN 'High Value'
        WHEN amount >= 500 THEN 'Medium Value'
        ELSE 'Low Value'
    END;

CASE WHEN for age groups

SELECT
    customer_id,
    age,
    CASE
        WHEN age < 25 THEN 'Under 25'
        WHEN age < 40 THEN '25-39'
        WHEN age < 60 THEN '40-59'
        ELSE '60+'
    END AS age_group
FROM customers;

CASE WHEN for performance classification

Suppose you want to classify regions by revenue. 

SELECT
    region,
    SUM(amount) AS revenue,

    CASE
        WHEN SUM(amount) >= 1000000 THEN 'Excellent'
        WHEN SUM(amount) >= 500000 THEN 'Good'
        WHEN SUM(amount) >= 100000 THEN 'Average'
        ELSE 'Low'
    END AS performance

FROM sales
GROUP BY region;

CASE WHEN inside ORDER BY

You can also use CASE WHEN to create custom sorting logic. 

SELECT
    customer_name,
    customer_type
FROM customers
ORDER BY
    CASE
        WHEN customer_type = 'VIP' THEN 1
        WHEN customer_type = 'Premium' THEN 2
        ELSE 3
    END;

Common mistake: overlapping conditions

Imagine: 

CASE
    WHEN amount >= 500 THEN 'Medium'
    WHEN amount >= 1000 THEN 'High'
END

This is wrong logically because values above 1000 also satisfy the first condition.

Better: 

CASE
    WHEN amount >= 1000 THEN 'High'
    WHEN amount >= 500 THEN 'Medium'
    ELSE 'Low'
END

Common analyst use cases

  • customer segmentation
  • risk flags
  • active vs inactive users
  • product categories
  • sales performance bands
  • regional classifications
  • conditional KPIs
  • data quality flags

Practical example

Suppose you want to segment customers based on their total revenue. 

SELECT
    customer_id,
    SUM(amount) AS total_revenue,

    CASE
        WHEN SUM(amount) >= 10000 THEN 'High Value'
        WHEN SUM(amount) >= 5000 THEN 'Medium Value'
        ELSE 'Low Value'
    END AS customer_segment

FROM sales
GROUP BY customer_id
ORDER BY total_revenue DESC;

Quick checklist

  • What condition are you testing?
  • Are the most specific conditions first?
  • Do you need an ELSE?
  • Are conditions mutually exclusive?
  • Can CASE WHEN simplify your KPI logic?
  • Are you using it inside SUM or COUNT where useful?
