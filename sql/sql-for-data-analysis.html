SQL for Data Analysis

SQL is one of the most important tools for data analysts because it allows you to extract, filter, combine and summarise data directly from databases.

In practice, analysts use SQL to answer business questions such as:

  • How much revenue did we generate this month?
  • Which customers spent the most?
  • Which products are growing fastest?
  • How many active users do we have?
  • Which regions are underperforming?

1. Selecting data

The SELECT statement is used to retrieve columns from a table. 

SELECT
    customer_id,
    customer_name,
    country
FROM customers;

To retrieve every column: 

SELECT *
FROM customers;
Good practice: in production analysis, selecting only the columns you actually need is usually clearer and more efficient than using SELECT *.

2. Filtering data with WHERE

Analysts rarely need every row in a database. The WHERE clause lets you filter the data. 

SELECT *
FROM sales
WHERE country = 'Italy';

You can combine several conditions: 

SELECT *
FROM sales
WHERE country = 'Italy'
  AND sales_amount > 1000;

3. Sorting results

Use ORDER BY to sort results. 

SELECT
    customer_name,
    sales_amount
FROM sales
ORDER BY sales_amount DESC;

DESC sorts from highest to lowest. ASC sorts from lowest to highest.

4. Aggregating data

SQL is especially useful for calculating KPIs.

Common aggregation functions include:

  • SUM()
  • AVG()
  • COUNT()
  • MIN()
  • MAX()

Example: 

SELECT
    SUM(sales_amount) AS total_sales
FROM sales;

5. GROUP BY

GROUP BY lets you calculate metrics for categories.

For example, sales by country: 

SELECT
    country,
    SUM(sales_amount) AS total_sales
FROM sales
GROUP BY country;

Or number of customers by region: 

SELECT
    region,
    COUNT(DISTINCT customer_id) AS customers
FROM sales
GROUP BY region;

6. Filtering aggregated results with HAVING

WHERE filters rows before aggregation. HAVING filters groups after aggregation. 

SELECT
    country,
    SUM(sales_amount) AS total_sales
FROM sales
GROUP BY country
HAVING SUM(sales_amount) > 100000;

7. Joining tables

Data is usually stored across multiple tables. SQL joins allow analysts to combine those tables.

Imagine: 

customers
---------
customer_id
customer_name
country

sales
-----
sale_id
customer_id
sales_amount

You can combine them using: 

SELECT
    c.customer_name,
    c.country,
    s.sales_amount
FROM sales s
LEFT JOIN customers c
    ON s.customer_id = c.customer_id;

8. Creating business KPIs

SQL can calculate metrics that later feed dashboards in tools such as Power BI.

Example: 

SELECT
    COUNT(DISTINCT order_id) AS total_orders,
    COUNT(DISTINCT customer_id) AS unique_customers,
    SUM(sales_amount) AS total_revenue,
    AVG(sales_amount) AS average_order_value
FROM sales;

9. CASE WHEN

CASE WHEN lets you create categories based on conditions. 

SELECT
    customer_id,
    sales_amount,
    CASE
        WHEN sales_amount >= 1000 THEN 'High Value'
        WHEN sales_amount >= 500 THEN 'Medium Value'
        ELSE 'Low Value'
    END AS customer_segment
FROM sales;

This is extremely useful for segmentation and business reporting.

10. Finding duplicates

Data analysts often need to identify duplicate records. 

SELECT
    customer_id,
    COUNT(*) AS number_of_rows
FROM customers
GROUP BY customer_id
HAVING COUNT(*) > 1;

11. Working with NULL values

Missing values in SQL are represented by NULL.

To find them: 

SELECT *
FROM customers
WHERE email IS NULL;

To replace a NULL value: 

SELECT
    customer_name,
    COALESCE(country, 'Unknown') AS country
FROM customers;

12. A typical analyst workflow

A real analysis might follow this process:

  1. Identify the business question.
  2. Find the relevant tables.
  3. Join the required data.
  4. Filter irrelevant records.
  5. Create KPIs.
  6. Check missing values and duplicates.
  7. Validate the results.
  8. Send the result to Power BI, Excel or another reporting tool.

Example: sales analysis

Suppose management asks:

Which five countries generated the most revenue?

A query could be: 

SELECT
    country,
    SUM(sales_amount) AS total_revenue
FROM sales
GROUP BY country
ORDER BY total_revenue DESC
LIMIT 5;

Depending on the SQL database you use, the syntax for limiting rows may differ.

What should a data analyst learn next?

Once you understand the basics, the most useful SQL topics for data analysis include:

  • JOINs
  • GROUP BY and HAVING
  • CASE WHEN
  • subqueries
  • CTEs
  • window functions
  • ROW_NUMBER
  • RANK and DENSE_RANK
  • LAG and LEAD
  • running totals
  • month-over-month analysis
