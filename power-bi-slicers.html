Power BI Slicers Explained

Slicers are interactive filters that allow users to control what data is shown in a Power BI report.

They are especially useful for filtering by date, category, region, customer, product or any other field in your model.

What is a slicer?

A slicer is a visual that displays values from a column and lets the user select one or more of those values.

For example, you could create a slicer using: 

Products[Category]

If the user selects Electronics, the other visuals on the page can update to show only electronics data.

How to create a slicer

  1. Add a slicer visual to the report canvas.
  2. Drag the field you want to filter by into the slicer.
  3. Choose the slicer style you prefer.

Common slicer styles include:

  • List
  • Dropdown
  • Tile
  • Date range

Single select vs multiple select

You can control whether the user can select one value or multiple values.

Single select is useful when the report should focus on only one item at a time.

Multiple select is useful when users need to compare several categories or regions.

Date slicers

Date slicers are commonly used to filter reports by time.

Depending on the configuration, users can select:

  • a specific date
  • a date range
  • before or after a date
  • relative periods such as the last 30 days
Tip: for time-based reporting, use a proper calendar table rather than relying only on date columns from your fact table.

Why is my slicer not filtering a visual?

If a slicer is not affecting another visual, check visual interactions.

Select the slicer, then go to: 

Format → Edit interactions

Make sure the filter interaction is enabled for the visual you want to control.

Check relationships

A slicer can only filter data correctly when the tables in your model are related properly.

For example, if your slicer uses: 

Products[Category]

the Products table needs a valid relationship with the fact table used in your measures.

Use dimension fields in slicers

In a star schema, it is usually better to use dimension fields in slicers.

For example: 

DIM_PRODUCT[Category]

is generally preferable to using a repeated category column directly from a large fact table.

Slicer sync across pages

Power BI allows slicers to be synchronised across multiple report pages.

This is useful when you want a selection made on one page to continue filtering other pages in the report.

Common slicer problems

1. The slicer does not filter one visual

Check visual interactions.

2. The slicer shows unexpected values

Check the source column, model relationships and whether blank values exist.

3. Multiple slicers give confusing results

Remember that slicers can filter each other depending on your data model and interactions.

4. A measure ignores the slicer

Check whether the DAX measure uses functions such as: 

ALL()
REMOVEFILTERS()

These functions can remove filter context and make the measure appear unaffected by the slicer.

Quick checklist

  • Is the correct field used in the slicer?
  • Are the tables related correctly?
  • Are visual interactions enabled?
  • Is the slicer set to single or multiple selection as intended?
  • Does your DAX measure remove filters?
  • Are synced slicers affecting other pages?
